# Energy Detective：分析方法與評估計畫

本文件為初版設計基準，尚未訓練模型或執行實驗。數值門檻、樣本數與參數為本專案的提案設定，並非經文獻驗證的最佳設定。

## 1. 配置總覽

| 項目 | 初版配置 | 理由與限制 |
|---|---|---|
| 預測 | Random Forest Regressor | 作為單一機器學習候選；與簡單方法比較後才能判斷是否有效，不假設一定較好。 |
| 預測基準 | 上一小時、前一天同時段 | 檢查模型是否真的超越用電的持續性與日週期。 |
| 電量統計 | 只把完整小時當作完整觀測電量；不自動補值 | 避免把部分觀測或推估值寫成實測完整總量。 |
| 異常 | 相同時刻與日型歷史參考的中位數／MAD規則 | 可明確解釋比較基準；只標記候選，沒有真實故障或浪費標籤。 |
| 能源知識 | 約10條人工整理、附來源的知識條目 | 先確保可核對，依概念與關鍵詞檢索；不先引入向量資料庫。 |
| 回答檢查 | 結構化數值、期間、單位、方向、證據與限制標記 | 可客觀核對的部分先做規則檢查；建議合理性另由人工評估。 |
| 失敗處理 | 最多1次回答修正；每任務最多8次Agent工具呼叫 | 限制迴圈與成本；工具失敗亦計入預算，用完則說明限制。 |
| Agent評估 | 10題獨立試測、另50題正式題；兩條件，各重複3次 | 分開開發與測試；同模型比較有無外部檢查，衡量穩定性。 |

RF與時間序列驗證的官方文件見[10][11]；MAD規則參考NIST[12]。完整實驗需另外記錄實際套件版本；瀏覽文件版本不等於已安裝版本。

## 2. 資料與時間的明確定義

### 2.1 預測時間

以原始紀錄的時鐘時間定義每小時區間[h,h+1)，不自行轉成台灣時間。回放截至時間為小時邊界h，Agent只能取得時間戳小於h的真實觀測；下一小時目標為區間[h,h+1)的電量，記為y_h。

例如回放時間為14:00，最近完成的小時是13:00–14:00，目標為14:00–15:00。查詢「昨天」則依回放日期解讀。原始分鐘平均值依所標記的分鐘歸入區間，不推定感測器未記載的傳輸延遲或瞬時峰值。

### 2.2 單位換算

- 全屋平均用電功率（總有功功率）P_i 以 kW 記錄，每筆代表一分鐘的平均值；完整小時電量為 Σ(P_i/60)，單位為 kWh。
- 設備群每分鐘的用電量 e_i 以 Wh 記錄；完整小時電量為 Σ(e_i)/1000，單位為 kWh。
- 日總量為完整日期內的分鐘電量總和；日期是否完整須檢查，不直接把部分起訖日當全天。
- 所謂「最高用電時段」本案指小時電量最高的區間，不聲稱是瞬間最大功率。

以上換算依 UCI 欄位定義 [7] 推導；全屋功率欄位與設備群電量欄位須分別使用對應公式。

### 2.3 完整性與缺值

1. 依所查欄位分別檢查資料；其他不使用欄位缺值，不自動否決可用欄位。
2. 每小時所需60個不同分鐘均有有效數字，才產生該欄位的完整觀測電量。NaN、非數值及未解決的衝突紀錄不能當零。
3. 同時間戳且內容完全一致的重複列可去重並記錄；數值衝突則標為無法確認，不任意挑選。
4. 未完整時段只回報已觀測部分、涵蓋率及限制，不輸出未標明的外推總量；本版不自動補值。
5. 完整日需依原始時鐘格網核對分鐘是否齊全；不完整日期不稱完整全天實測值，也不以不完整基準計算全日增減百分比。
6. 百分比變化以比較基準為分母；分母為零時只報絕對差異，百分比標不適用。

這是保守的初版策略，會犧牲部分可分析資料。後續需報告被排除時段比例；若要加入補值，另定方法及敏感度評估，不在測試後為提高分數臨時改規則。

## 3. 下一小時用電預測

### 3.1 兩個基準與一個候選模型

| 方法 | 預測y_h的方式 |
|---|---|
| Persistence | 使用y_(h-1)，即上一個完整小時。 |
| Daily Seasonal Naive | 使用y_(h-24)，即前一天相同時段。 |
| Random Forest Regressor | 從預測時點以前的歷史與已知時間特徵學習非線性關係。 |

RF初始參數建議：n_estimators=200、max_depth=12、min_samples_leaf=5、random_state=42。這是可調整的提案起點，不是經驗證的最優參數。若需調整，僅能使用訓練／驗證區間並記錄所有選擇，在最終測試前凍結。

### 3.2 特徵

- 過去電量：y_(h-1)、y_(h-2)、y_(h-24)、y_(h-168)。
- 最近3個、24個完整小時的平均與標準差，計算區間結束於h，不含目標小時。
- 已知時間：目標小時、星期幾、月份及週末標記；日型僅是日曆代理，不代表實際家庭作息。
- 不使用當前資料未提供的氣象、住戶活動、台灣費率或設備開關狀態。

所需特徵時段缺失時，不生成該RF預測。若基準資料足夠，可以清楚標示為基準估計，不冒充RF輸出。只需要特徵實際使用的時段完整，不要求相隔168小時的整段資料全部完整。

### 3.3 切分與評估

先在完整時間格網上，依時間由早到晚定義70%訓練、15%驗證、15%測試邊界，再按資料完整性建立可用樣本；不先刪除缺值後把不連續列誤當等距時間。訓練標籤只來自訓練區間，最終模型在設定凍結後可合併訓練與驗證資料重訓一次，再測試。

測試採逐小時歷史回放的一步預測：每個時點可使用當時已完成的實際過去小時，包括較早的測試小時，但不使用未來或目標小時。這不是一次預測整段測試期；模型不在測試中反覆調參。

模型檔需記錄訓練資料與標籤的截止時間；其截止不得晚於回放截至時間h。不能用後期資料訓練的模型回到較早日期預測，否則即使輸入特徵只有過去值，仍可能洩漏未來。正式Agent題集的回放時點選在最終測試區間；若之後允許更早回放，必須使用當時可用的模型，或說明沒有符合時間條件的模型。

三方法在共同可用、且目標實際值完整的測試時點比較MAE、RMSE（kWh），另報各方法可產生預測的比例與樣本數。可附月份／高用電時段分組，但不只挑選好看的月份。未通過資料條件的樣本另報排除原因；不把缺值目標補成標準答案。

## 4. 異常候選辨識

### 4.1 參考集合

對目標小時，從它之前56天取相同時刻、相同「平日／週末」日型且資料完整的紀錄。至少14筆才判定；不足則說明參考資料不足。若一次分析多個目標小時，每個小時均只使用它之前的紀錄作參考。

此集合能部分控制時刻與日型，但無法控制未提供的氣象、假日、住戶活動及季節突變；不可當成真實相同情境。

### 4.2 判定

令m為參考集合中位數、MAD為median(|x_i-m|)，計算修正分數M=0.6745×(x-m)/MAD，初值以|M|>3.5標記候選[12]。

- 56天、14筆與日型分組是本組初始設定；NIST沒有為本案驗證這些參數。
- 3.5為啟發式標記門檻，不是已校準的顯著水準、故障機率或對家庭用電的保證。
- MAD為零或資料不足時，不除以任意小數強行製造高分；只呈現可核對差異，說明無法用本規則穩定判定。
- 高低值均可標記；原始資料保留，除非另有證據證明是量測錯誤。

### 4.3 如何驗證

本資料沒有真實故障／浪費標籤，不報真實故障辨識Accuracy或F1。先檢查公式、時間隔離及邊界處理，再以案例圖表檢視標記與參考是否合理。可在驗證區間比較2.5／3.5／4.5的標記頻率以說明敏感度；這不是以無標籤資料宣稱找到了正確門檻。

若後續透過修改資料來模擬異常，只能驗證系統是否能辨識這些人為設定的情況，不能直接代表它能偵測真實家庭中的異常用電。

## 5. 知識條目與回答檢查

### 5.1 約10條有來源的知識條目

初步涵蓋：功率與電量、設備群資料的判讀限制、缺值、比較基準、零分母、異常候選、預測限制、節電／省費／削峰的差異、建議與行為成效，以及跨家庭適用限制。每條知識均包含定義、適用條件、不能推論的事項與來源編號。

以概念標籤及關鍵詞取得小型候選條目，再由Agent選擇相關內容；無匹配時不假造檢索結果。此配置先不承諾向量資料庫，也不以檢索到文字就判定建議正確。

### 5.2 結構化回答

回答草稿分為：使用者問題的時間解讀、數值結果、可引用證據ID、觀察／預測／假設分類、建議與限制。前台文字與圖表由同一結果ID產生或核對。紀錄工具輸入輸出，不要求保存模型內部思考過程。

比對數值時，允許四捨五入及電腦浮點運算造成的微小誤差。例如，保留兩位小數時，四捨五入的容許差距為 0.005，另保留浮點運算所需的極小容差。增減方向、百分比分母、時間範圍與單位須分別檢查，不能僅因數值接近就忽略日期錯誤。

系統預計自動核對回答中的日期、數值、單位與引用，並檢查是否違反明確限制，例如在缺乏個別電器資料時，直接斷定某台電器造成用電增加。其他較難用固定規則判斷的推論與建議，則由人工評分確認是否有足夠依據。

### 5.3 工具及修正上限

每個任務最多8次Agent發起的工具呼叫，失敗呼叫也計入；工具內部的一致性檢查不額外算Agent呼叫。回答檢查後最多再產生1次修正版，且所有後續工具仍受同一8次上限限制。再次失敗時回傳可確認部分或限制說明，記錄未完成原因。

數值規則檢查本身不必再次呼叫LLM；修正需要的額外模型回合及工具成本須在評估中記錄。

## 6. Agent的對照評估

### 6.1 題集

- 獨立試測 10 題：與正式題目分開，用於調整工具說明與題目格式，不列入正式評估結果。
- 正式50題：五類任務各10題；每類6題一般情境、4題資料不足或邊界情境，共30題一般、20題邊界。
- 正式題的回放截至時間選在最終測試區間，並遵守模型訓練截止限制；歷史比較可查更早紀錄，但不得因此讓模型學到未來標籤。
- 每題固定回放時點、資料視圖、標準答案或應澄清／說明限制的行為，以及評分規則。
- 遮蔽資料或模擬工具失敗只發生在測試視圖，不改原始檔；預期答案必須以該視圖實際可用資料為準。
- 正式題集在測試前凍結；不因模型答錯而重新解釋答案。題目由組員複核，不能全部依賴同一LLM產生及評分。

### 6.2 兩個條件

| 條件 | 固定內容 | 差異 |
|---|---|---|
| A：無外部回答檢查 | 同一LLM版本、工具、知識、資料、任務、回答格式與初始提示 | 生成回答後直接交離線評估，不啟用⑦的外部檢查與修正。 |
| B：有外部回答檢查 | 與A相同 | 啟用⑦、至多1次修正及限制回覆；受相同工具上限。 |

兩者均可自行澄清，均保留⑥證據紀錄供評估，不把「沒有檢查」誤作「沒有工具或知識」。比較的是整個檢查／修正方案的效果，不能把增加推理回合的影響全部歸因於某一條規則；同步報告時間與成本。

每條件每題執行3次，共50×2×3=300次任務執行，另有獨立試測。一次任務可包含多次模型回合，因此不是300次API呼叫，也不是目前已執行300次。LLM供應商、固定模型ID與可用生成參數待選定；未取得模型服務前不聲稱已完成實驗。

### 6.3 指標與避免偏誤

| 面向 | 定義／計畫 |
|---|---|
| 任務完成率 | 按各題凍結標準評分；一般題須給必要結果，邊界題須做正確的澄清或限制處理。 |
| 數字／單位／時間正確性 | 一般可回答題按預期必要欄位計分；缺答必要欄位算失敗，不只計算已輸出的漂亮數字。 |
| 證據一致性 | 檢查可核對主張與實際證據是否一致，同時報告回答覆蓋與任務完成率，避免少說或拒答取得表面高分。 |
| 適當限制處理 | 對20題邊界情境報告正確澄清／限制率；對30題一般情境另報不必要拒答率。 |
| 建議品質 | 兩位組員獨立評分相關題：證據支持、推論界線、可採取性，各0–2分；報初始一致情況並記錄分歧處理。合理性不以LLM自評為唯一依據。 |
| 執行成本 | 每題時間、Agent工具呼叫次數、修正次數、模型用量與可取得的費用紀錄。 |
| 穩定性 | 報告各次執行及各題結果，不只挑最佳一次；相同題目重複結果不當成彼此獨立的不同問題。 |

沒有預設必須提升幾個百分點的結論。若B無改善、較慢或拒答較多，也應如實報告並分析。
