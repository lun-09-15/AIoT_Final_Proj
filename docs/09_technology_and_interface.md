# Energy Detective：技術與介面方案

## 1. 技術方向

- 使用單一、支援結構化工具調用的雲端LLM；供應商、固定模型ID、實際可用性與用量設定留待實作前確認。
- 介面採Streamlit，整合聊天、用電圖表、可查核的證據與限制；目前不實作或部署網站。
- RF負責數值預測，LLM負責需求與工具協調，不將兩者混為一個模型。

## 2. 雲端LLM的能力需求

| 需求 | 對本專案的意義 |
|---|---|
| 工具調用 | 以結構化名稱與參數請求既定工具；由應用執行並回傳結果，再由模型繼續處理。 |
| 多步協調 | 支援依工具結果選下一步、提出澄清及整合證據。 |
| 可記錄版本 | 正式測試前記錄供應商、固定模型ID、參數及日期，不以浮動別名代替完整紀錄。 |
| 可取得用量 | 盡可能記錄輸入輸出用量、延遲與費用；查核實際帳號額度及限制。 |

OpenAI官方文件展示工具調用的模型／應用分工[13]，可作候選服務的能力參考，不代表已決定採OpenAI或已完成呼叫。

實作前需查核候選 API 的帳號資格、可用額度及費用，不預設已有免費額度[14]。

選定供應商後，先以獨立的 10 題進行試測，確認工具格式、時間限制、錯誤處理與成本，再凍結正式評估設定。試測結果不列入正式評估。服務改版時須記錄版本差異；實作前仍需核對最新文件。

## 3. Streamlit畫面配置初稿

此為文件中的介面規劃，尚未製作互動原型。Streamlit官方提供聊天與圖表元件[15][16]，適合在同一介面呈現本案功能；實際體驗仍需實作後檢查。

| 區域 | 顯示內容 | 設計目的 |
|---|---|---|
| 回放與資料設定 | 回放日期／小時、資料可見截至時間、可用資料範圍 | 讓使用者知道目前分析的是哪段歷史。 |
| 用電摘要 | 選定區間電量、最高用電時段、資料完整性 | 先呈現可確認的基本事實；缺值時用已觀測標籤。 |
| 對話區 | 自然語言提問、澄清、回答與追問 | 支援五類情境，不要求使用者懂演算法或模組名稱。 |
| 分析圖表 | 與回答同區間的趨勢、比較、候選異常或預測 | 避免文字與圖表引用不同資料。 |
| 證據與限制 | 可展開的區間、比較依據、方法名稱、來源及不足 | 需要時能查核，又不讓內部工程資訊佔滿主要畫面。 |

不在一般使用者畫面直接堆放模組編號、程式堆疊、API金鑰或模型內部思考。評估所需的工具紀錄及用量保存於研究紀錄，不要求使用者閱讀。

## 4. 本階段與實作階段

| 現在的Proposal工作 | 後續實作前／實作時的工作 |
|---|---|
| 描述雲端LLM能力需求與Streamlit介面 | 選供應商與固定模型版本，查核帳號、用量與可用性 |
| 整合研究、架構、流程、虛擬碼及評估 | 下載原始數據、訓練、工具與知識條目實作 |
| 準備Proposal文件與PPT | 建立Streamlit畫面、執行獨立試測與正式評估 |

現在沒有已運作的API串接、App、介面測試或節電結果。所有展示若是設計示意，文件與PPT須明確標示。
